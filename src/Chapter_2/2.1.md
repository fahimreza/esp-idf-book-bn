# অধ্যায় ২: এনভায়রনমেন্ট সেটআপ (Windows)

ESP মাইক্রোকন্ট্রোলার প্রোগ্রামিং-এর জন্য বেশ কিছু প্রচলিত পদ্ধতি রয়েছে। যেমন:

1. ESP-IDF Command Prompt ব্যবহার করে
2. Espressif-IDE ব্যবহার করে
3. Arduino Framework ব্যবহার করে
4. ESP-IDF VSCode Extension ব্যবহার করে

তবে উপরের প্রতিটি পদ্ধতিরই কিছু না কিছু drawback (সীমাবদ্ধতা) রয়েছে। আমি চেষ্টা করব **ESP-IDF Framework + VS Code**-এর সংমিশ্রণে একটি **Clean Interface** ব্যবহার করে ESP32 প্রোগ্রামিং শেখানোর, যাতে একই সাথে **Easy Interface** এবং **Latest Espressif Release** ব্যবহারের এক দুর্দান্ত অভিজ্ঞতা পাওয়া যায়।

---

## ২.১ এই অধ্যায়ে আমরা কী শিখব?

প্রথম অধ্যায়ে আমরা জেনেছি *Embedded System*, *ESP32*, এবং *ESP-IDF* কী। এখন হাতে-কলমে কাজ শুরু করার পালা। এই অধ্যায়ে আমরা `Windows Operating System (OS)` চালিত কম্পিউটারে এমন একটি এনভায়রনমেন্ট তৈরি করব, যেখানে প্রোজেক্ট তৈরি করা, বিল্ড করা, এবং বোর্ডে আপলোড (Flash) করার মতো জটিল কাজগুলো খুব সহজেই করা যায়।

> **নোট**: Windows এবং macOS-এ ইনস্টলেশনের ধাপ কিছুটা ভিন্ন। এই অংশে আমরা **Windows**-এর জন্য পুরো প্রক্রিয়াটি দেখব, এবং পরের অংশে **macOS**-এর জন্য আলাদাভাবে এনভায়রনমেন্ট তৈরি করা শিখব। আপনি যদি macOS ব্যবহার করেন, তাহলে সরাসরি পরের অধ্যায়ে চলে যেতে পারেন।

**আমরা ধাপে ধাপে যা করব:**

1. Visual Studio Code (VS Code) ইনস্টল করা (কোড এডিটর হিসেবে)
2. ESP-IDF Installation Manager (EIM) ডাউনলোড করা
3. EIM দিয়ে ESP-IDF ফ্রেমওয়ার্ক ইনস্টল করা
4. ESP-IDF দিয়ে প্রয়োজনীয় টুলস ইনস্টল করা
5. New Project তৈরি এবং বিল্ড করা
6. ESP32-তে প্রোগ্রাম আপলোড করা

> **নোট**: ESP-IDF Framework-এর ভার্সন নম্বর মাঝেমধ্যে আপডেট হয়। এই অধ্যায়টি লেখার সময় (২০২৬) ESP-IDF Installation Manager (EIM)-এর মাধ্যমে সর্বশেষ সংস্করণ **ESP-IDF v6.0.2** ইনস্টল করা হয়েছে এবং তারই screenshot ব্যবহার করা হয়েছে। ভবিষ্যতে ভার্সন নম্বরে সামান্য পরিবর্তন দেখলে ঘাবড়াবেন না — মূল ধারণাটি সবসময় একই থাকবে।

## ২.২ প্রয়োজনীয় জিনিসপত্র

**পরবর্তী ধাপ শুরু করার আগে নিশ্চিত হয়ে নিন যে আপনার কাছে রয়েছে:**

- স্ট্যাবল ইন্টারনেট কানেকশন (ডাউনলোড করতে 1-2 GB পর্যন্ত ডেটা লাগতে পারে)

- একটি ভালো মানের USB ক্যাবল (শুধু চার্জিং না, ডেটা ট্রান্সফার সাপোর্ট করে এমন ক্যাবল হতে হবে)

## ২.৬ ESP-IDF দিয়ে প্রয়োজনীয় টুলস ইনস্টল করা
আগের ধাপে আমরা EIM দিয়ে C: ড্রাইভের নির্দিষ্ট লোকেশনে (C:\esp\v6.0.2\esp-idf) এর মধ্যে ESP-IDF ইনস্টল করেছি। ফোল্ডারটি ওপেন করলে install.bat, export.bat-এর মতো বেশ কিছু স্ক্রিপ্ট ফাইল দেখতে পাবেন। ESP-IDF এগুলো ব্যবহার করে Windows-এর জন্য প্রয়োজনীয় সফটওয়্যার এর সমন্বয়ে একটি Environment তৈরি করে, যেখানে ESP-কে প্রোগ্রাম করার জন্য প্রয়োজনীয় কমান্ড `run` করা যায়।

এই `install.bat` ফাইলটি রান করলে ESP-IDF কম্পাইল করার জন্য প্রয়োজনীয় সব টুল (`কম্পাইলার`, `Python প্যাকেজ`, ইত্যাদি) স্বয়ংক্রিয়ভাবে ডাউনলোড ও ইনস্টল হতে শুরু করে। এ সময় লক্ষ্য করলে টার্মিনালে দেখতে পাবেন কোন কোন টুল ইনস্টল হচ্ছে (যেমন `xtensa-esp-elf-gdb`, `riscv32-esp-elf-gdb`, `cmake`, `ninja`, `ccache`, `dfu-util` ইত্যাদি):

### ২.৬.৫ ESP-IDF এনভায়রনমেন্ট অ্যাক্টিভেট করা
এখানে মনে একটি প্রশ্ন আসতে পারে — টুলস ইনস্টল করা হয়েছে, তাহলে আবার "অ্যাক্টিভেট" করার দরকার কী?

আসলে EIM যে টুলগুলো (Python, কম্পাইলার, idf.py স্ক্রিপ্ট ইত্যাদি) ইনস্টল করেছে, সেগুলো সাধারণ কোনো প্রোগ্রামের মতো সরাসরি Windows-এর PATH-এ যোগ হয়নি — বরং একটা নির্দিষ্ট, আলাদা লোকেশনে (.espressif ফোল্ডারের ভেতরে) রাখা হয়েছে, যাতে অন্য কোনো সফটওয়্যারের সাথে conflict না হয়। ফলে যদি আপনি এখনই একটা নতুন টার্মিনাল খুলে idf.py লেখেন, Windows সেই কমান্ডটা চিনবে না — কারণ টার্মিনালটা জানেই না এই টুলগুলো কোথায় আছে।

"অ্যাক্টিভেট করা" মানে হলো — এই নির্দিষ্ট টার্মিনাল সেশনের জন্য সাময়িকভাবে PATH এবং অন্যান্য প্রয়োজনীয় Environment Variable সেট করে দেওয়া, যাতে টার্মিনালটা জানতে পারে ঠিক কোথায় গিয়ে idf.py, Python, কম্পাইলার ইত্যাদি খুঁজে পেতে হবে। এই কাজটিই করে export.bat স্ক্রিপ্ট। এই সেটিংস শুধু ওই একটা টার্মিনাল সেশনের জন্যই প্রযোজ্য — টার্মিনাল বন্ধ করে আবার নতুন করে খুললে আবার export.bat চালাতে হবে।

## ২.৮ ESP32-তে প্রোগ্রাম আপলোড করা 
আপনার কাছে থাকা ESP32 Microcontroller-এ প্রোগ্রাম আপলোড করতে, নিচের ধাপগুলো অনুসরণ করুন: 
1. প্রোগ্রাম আপলোড করতে সর্বপ্রথম ESP32 Dev Kit V1 কে USB Cable এর সাহায্যে কম্পিউটারের সাথে connect করতে হবে। 

2. ESP বোর্ডে থাকা USB-to-Serial চিপ কম্পিউটারের সাথে যোগাযোগের জন্য COMxx Port তৈরি করে। বোর্ডটি কম্পিউটারের কোন COMxx পোর্টে কানেক্ট হয়েছে, তা Device Manger থেকে খুব সহজেই চেক করা যায়। এ জন্য কম্পিউটারের Start বাটন ক্লিক করে, Device Manager লিখে সার্চ করে App টি সিলেক্ট করতে হবে। 

<figure align="center">
    <img src="../../Image/CH2/EIM/42-Device-Manager-App.png" width="50%">
    <figcaption>Figure: Device Manager</figcaption>
</figure>

ESP বোর্ডে USB to Serial Communication এর জন্য সাধারণত **CP2102** অথবা **CH340** চিপ ব্যবহার করা হয়। 

আপনার বোর্ডে কোন চিপ ব্যবহার করা হয়েছে তা বোর্ডের ছোট IC-গুলোর গায়ে লেখা নাম পড়ে নিতে পারেন, অথবা Device Manager-এর **Ports (COM & LPT)** সেকশনে বোর্ড কানেক্ট করার পর নতুন কোন COM পোর্ট (যেমন `COM5`) তৈরি হচ্ছে সেটা দেখেও নিশ্চিত হতে পারেন।

    <figcaption>Figure: USB to UART Bridge (COM5)</figcaption>

যেমন আমার কম্পিউটারে **CP210x USB to Serial** ড্রাইভার চিপ `COM5` পোর্ট তৈরি করেছে। এই পোর্ট-নম্বরটি খুবই গুরুত্বপূর্ণ, এটি ব্যবহার করেই আমরা পরবর্তীতে ESP-তে প্রোগ্রাম আপলোড বা সিরিয়াল-ডেটা প্রিন্ট করার মত কাজ গুলো করতে পারবো।

## ২.৯ সাধারণ সমস্যা ও সমাধান
| সমস্যা | সম্ভাব্য কারণ ও সমাধান |
|---|---|
| **"Insufficient permissions to install drivers"** — EIM-এ Install Drivers বাটনে ক্লিক করলে এই এরর আসছে | ড্রাইভার ইনস্টল করতে Windows-এ সবসময় Administrator পারমিশন লাগে। EIM বন্ধ করুন, `eim-gui-windows-x64.exe` ফাইলে রাইট-ক্লিক করে **Run as administrator** সিলেক্ট করুন, তারপর আবার Install Drivers-এ ক্লিক করুন। |
|`export.bat` ফাইল `run` করলে **ERROR** আসছে |সম্ভবত `C:\esp\v6.0.2\esp-idf` এই লোকেশন থেকে `install.bat` ফাইলটি `run` করা হয়নি! (প্রথমবার EIM ইনস্টলেশনের পর একবার `install.bat` ফাইলটি `run` করা বাধ্যতামূলক) |
| `idf.py --version` চালালে **"idf.py is not recognized"** জাতীয় এরর দেখাচ্ছে | এর মানে ESP-IDF এনভায়রনমেন্ট অ্যাক্টিভেট হয়নি। ঠিক esp-idf ফোল্ডারে (`cd C:\esp\v6.0.2\esp-idf`) আছেন কিনা এবং তারপর `export.bat` চালিয়েছেন কিনা যাচাই করুন। মনে রাখবেন, প্রতিটা নতুন টার্মিনালে আবার এই দুই ধাপ করতে হয়। |
| `install.bat` / `export.bat` চলাকালীন ডাউনলোড খুব ধীর বা আটকে গেছে মনে হচ্ছে | ইন্টারনেট কানেকশন চেক করুন। টুলচেইনের কিছু ফাইল বেশ বড় সাইজের, তাই ধীরগতির কানেকশনে স্বাভাবিকের চেয়ে বেশি সময় লাগতে পারে — ধৈর্য ধরে অপেক্ষা করুন। |
| বোর্ড USB দিয়ে কানেক্ট করার পর Device Manager-এ কোনো নতুন COM পোর্ট দেখাচ্ছে না | USB ক্যাবল বদলে দেখুন (অনেক ক্যাবল শুধু চার্জিং সাপোর্ট করে, ডেটা ট্রান্সফার না)। এরপরও না দেখালে CP2102/CH340 ড্রাইভার ম্যানুয়ালি ইনস্টল করুন — EIM-এর **Install Drivers** বাটন দিয়ে, অথবা সরাসরি Silicon Labs (CP2102) বা WCH (CH340)-এর ওয়েবসাইট থেকে। |
| `idf.py flash` চালালে **"Could not open port"** বা **"Failed to connect"** এরর | সঠিক COM নম্বর ব্যবহার করছেন কিনা Device Manager-এ আবার চেক করুন। এছাড়া অন্য কোনো প্রোগ্রাম (যেমন Arduino IDE-এর Serial Monitor) যদি একই সময়ে সেই পোর্ট ব্যবহার করে থাকে, সেটা বন্ধ করুন — একই সিরিয়াল পোর্ট একসাথে দুটো প্রোগ্রাম ব্যবহার করতে পারে না। |
| Flash করার সময় বোর্ড সাড়া দিচ্ছে না, বারবার "Connecting..." দেখাচ্ছে | কিছু ESP32 Dev Kit V1 বোর্ডে ম্যানুয়ালি bootloader mode-এ যেতে হয় — **Boot** বাটন চেপে ধরে রাখুন, "Writing at 0x00010000..." মেসেজ দেখা গেলে ছেড়ে দিন (২.৮ সেকশনে বিস্তারিত আছে)। |

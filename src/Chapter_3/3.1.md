# অধ্যায় ৩: এনভায়রনমেন্ট সেটআপ (macOS)

## ৩.১ এই অধ্যায়ে আমরা কী শিখব?

দ্বিতীয় অধ্যায়ে আমরা Windows-এ ESP-IDF এনভায়রনমেন্ট সেটআপ করেছি। যারা macOS ব্যবহার করেন, তাদের জন্য এই অধ্যায়। মূল ধারণা একদম একই — VS Code + ESP-IDF Installation Manager (EIM), শুধু কমান্ড ও টুলগুলো macOS-এর উপযোগী।

> **নোট**: macOS এবং Windows-এ ইনস্টলেশনের ধাপ কিছুটা ভিন্ন। দ্বিতীয় অধ্যায়ে আমরা **Windows** এর জন্য এনভায়রনমেন্ট তৈরি করা শিখেছি, এই অংশে আমরা **macOS**-এর জন্য পুরো প্রক্রিয়াটি দেখব। আপনি যদি Windows ব্যবহারকারী হয়ে থাকেন, তাহলে সরাসরি পরের অধ্যায়ে চলে যেতে পারেন।

**আমরা ধাপে ধাপে যা করব:**

1. Visual Studio Code (VS Code) ইনস্টল করা (কোড এডিটর হিসেবে)
2. Prerequisites (Homebrew দিয়ে) ইনস্টল করা
3. ESP-IDF Installation Manager (EIM) ইনস্টল করা
4. EIM দিয়ে ESP-IDF ফ্রেমওয়ার্ক ইনস্টল করা
5. ESP-IDF দিয়ে প্রয়োজনীয় টুলস ইনস্টল করা 
6. ESP-IDF এনভায়রনমেন্ট অ্যাক্টিভেট করা
7. New Project তৈরি এবং বিল্ড করা
8. ESP32-তে প্রোগ্রাম আপলোড করা

> **নোট**: ESP-IDF Framework-এর ভার্সন নম্বর মাঝেমধ্যে আপডেট হয়। এই অধ্যায়টি লেখার সময় (২০২৬) ESP-IDF Installation Manager (EIM)-এর মাধ্যমে সর্বশেষ সংস্করণ **ESP-IDF v6.0.2** ইনস্টল করা হয়েছে এবং তারই screenshot ব্যবহার করা হয়েছে। ভবিষ্যতে ভার্সন নম্বরে সামান্য পরিবর্তন দেখলে ঘাবড়াবেন না — মূল ধারণাটি সবসময় একই থাকবে।

### ৩.৪.১ Homebrew ইনস্টল করা
Homebrew হলো macOS-এর জন্য ব্যবহৃত একটি package manager। সহজভাবে বললে, এটি ব্যবহার করে Terminal দিয়ে বিভিন্ন সফটওয়্যার/টুল ইনস্টল, আপডেট ও ম্যানেজ করা যায়।

যেমন Homebrew ইনস্টল থাকলে Terminal-এ: 

```
brew install python
brew install git
brew install node
```

দিয়ে Python, Git বা Node.js ইনস্টল করা যায়। 

> **নোট**: `brew update` দিয়ে Homebrew-এর package information আপডেট করা এবং `brew upgrade` দিয়ে পুরোনো প্যাকেজ আপগ্রেড করা যায়। 

নিচের কমান্ডটি `run` করে নিশ্চিত হয়ে নিন যে, আপনার কম্পিউটারে আগে থেকেই Homebrew ইনস্টল করা আছে কিনা। যদি থাকে, তাহলে এই সেকশনটি এড়িয়ে গিয়ে সরাসরি **৩.৪.২ প্রয়োজনীয় প্যাকেজ ইনস্টল করা** থেকে অনুসরণ করুন।

## ৩.৫ ESP-IDF Installation Manager (EIM) ইনস্টল করা 

EIM ইনস্টল করার দুটো উপায় আছে — Homebrew দিয়ে, অথবা সরাসরি ডাউনলোড করে। তবে Homebrew দিয়ে (সহজ, ভবিষ্যতে আপডেট করাও সহজ)।

### ৩.৫.১ Homebrew-এ EIM-এর Tap যোগ করা
**Third-party repository যুক্ত করা:** যেহেতু espressif/eim Homebrew-এর নিজস্ব repository নয়, বরং Espressif-এর একটি Homebrew tap, তাই Homebrew-এর পরিভাষায় এটি একটি third-party tap। এই ধরনের tap-এর মাধ্যমে সরবরাহ করা package ইনস্টল করার আগে brew tap কমান্ড ব্যবহার করে Homebrew-এ সেই tap-টি যুক্ত করতে হয়। এর মাধ্যমে Homebrew জানতে পারে যে সংশ্লিষ্ট package-এর formula কোথায় পাওয়া যাবে।

```
brew tap espressif/eim
```
- brew → macOS-এর package manager Homebrew
- tap → Homebrew-এ কোনো third-party repository যোগ করে
- espressif/eim → Espressif-এর EIM-এর Homebrew tap

### ৩.৮ ESP-IDF এনভায়রনমেন্ট অ্যাক্টিভেট করা
এখানে মনে একটি প্রশ্ন আসতে পারে — টুলস ইনস্টল করা হয়েছে, তাহলে আবার "অ্যাক্টিভেট" করার দরকার কী?

আসলে EIM যে টুলগুলো (Python, কম্পাইলার, idf.py স্ক্রিপ্ট ইত্যাদি) ইনস্টল করেছে, সেগুলো সাধারণ কোনো প্রোগ্রামের মতো সরাসরি Operating System-এর PATH-এ যোগ হয়নি — বরং একটা নির্দিষ্ট, আলাদা লোকেশনে (.espressif ফোল্ডারের ভেতরে) রাখা হয়েছে, যাতে অন্য কোনো সফটওয়্যারের সাথে conflict না হয়। ফলে যদি আপনি এখনই একটা নতুন টার্মিনাল খুলে idf.py লেখেন, অপারেটিং সিস্টেম সেই কমান্ডটি চিনবে না — কারণ টার্মিনালটা জানেই না এই টুলগুলো কোথায় আছে।

"অ্যাক্টিভেট করা" মানে হলো — এই নির্দিষ্ট টার্মিনাল সেশনের জন্য সাময়িকভাবে PATH এবং অন্যান্য প্রয়োজনীয় Environment Variable সেট করে দেওয়া, যাতে টার্মিনালটা জানতে পারে ঠিক কোথায় গিয়ে idf.py, Python, কম্পাইলার ইত্যাদি খুঁজে পেতে হবে। এই কাজটিই করে export.sh স্ক্রিপ্ট। এই সেটিংস শুধু ওই একটা টার্মিনাল সেশনের জন্যই প্রযোজ্য — টার্মিনাল বন্ধ করে আবার নতুন করে খুললে আবার export.sh চালাতে হবে।

## ৩.১০ ESP32-তে প্রোগ্রাম আপলোড করা 
আপনার কাছে থাকা ESP32 Microcontroller-এ প্রোগ্রাম আপলোড করতে, নিচের ধাপগুলো অনুসরণ করুন: 
1. প্রোগ্রাম আপলোড করতে সর্বপ্রথম ESP32 Dev Kit V1 কে USB Cable এর সাহায্যে কম্পিউটারের সাথে connect করতে হবে। 

2. ESP বোর্ডে থাকা USB-to-Serial চিপ কম্পিউটারের সাথে যোগাযোগের জন্য একটি ডিভাইস ফাইল (device file) তৈরি করে। (এটা Windows-এর COM Port-এর সমতুল্য, তবে macOS-এ একে `/dev/cu.*` নামে চেনা যায়।) বোর্ডটি কম্পিউটারে কোন ডিভাইস ফাইল হিসেবে দেখা যাচ্ছে, তা Terminal থেকে খুব সহজেই চেক করা যায়। এ জন্য Terminal খুলুন (Spotlight থেকে `Cmd + Space` চেপে "Terminal.app" লিখে সার্চ করুন) এবং নিচের কমান্ডটি `run` করুন।

```
ls /dev/cu.*
```
